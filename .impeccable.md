## Design Context

### Users
Internal team split between two groups who use the admin dashboard simultaneously:
- **Supervisors** — non-technical, monitoring tagging quality, spotting escalations, spot-checking AI decisions
- **AI Engineers / Devs** — technical, watching confidence scores, debugging refusals, tuning thresholds

Both need to read data quickly. Neither group browses casually — they arrive with intent.

### Brand Personality
**Precise · Operational · Undecorated**

This is infrastructure tooling, not a product people fall in love with. The interface should feel like it was built by people who value correctness over aesthetics — but who care enough to get the spacing right. Think field manual, not SaaS marketing page.

### Aesthetic Direction
**Brutally minimal dark tool UI**

- Flat near-black background (`#0c0c0e`), no gradients
- Neutral accent palette — no LINE green (#06C755) on the admin side; that color belongs to the chat interface. Admin uses zinc + muted semantic colors only
- Status colors (emerald / amber / rose) are muted, never vivid — they signal state, not celebrate it
- Typography: **Figtree** for UI chrome (labels, buttons, headers); **Noto Sans Thai** for all Thai content; system monospace (`font-mono`) for data values (case IDs, scores, timestamps)
- No card shadows, no rounded-2xl blobs, no decorative borders
- Borders are 1px, very low opacity (`rgba(255,255,255,0.06)` range)
- Negative space does the heavy lifting

Anti-references: Glassmorphism dashboards, purple-gradient "AI tool" aesthetic, big-number hero metric cards with gradient accents.

References: Linear, Vercel dashboard, Resend — refined restraint, data-first, every pixel earning its place.

### Design Principles
1. **Data is the UI** — chrome should disappear; what the user is reading is the log entries, not the interface around them
2. **Earn every color** — status colors (emerald/amber/rose) appear only where they carry semantic meaning; neutral zinc for everything else
3. **Monospace for machine data** — indices, scores, timestamps, case IDs use `font-mono`; Thai text and labels do not
4. **Flat over layered** — avoid nested surfaces, avoid card-in-card, avoid gradients as backgrounds
5. **Functionality over flourish** — if a visual element doesn't help the user read or act faster, remove it
